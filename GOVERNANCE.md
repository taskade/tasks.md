# Governance

- The spec has one maintaining organization today: the reference implementation's team, which reviews every change.
- A second maintainer joins by shipping an implementation that reads and writes the format, then opening an issue that names it and asks for the role.
- A change to the section list, the `States:` line or the stamp grammar needs the agreement of every maintainer and one implementer besides the reference implementation.
- A change to prose only needs one maintainer's review.
- Decisions are recorded in the pull request that makes them. There is no separate decision log.
- There is no foundation, no steering committee, and no plan to create one.
